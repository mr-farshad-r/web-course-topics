Version Control is the system that records changes to files over time so you can recall specific versions later. It is arguably the single most important professional tool in software development — it enables team collaboration, rollback, branching, and accountability.

- Version Control System (VCS)
  - What is version control and why we need it
  - Local vs Centralized vs Distributed
    - Local ( RCS )
    - Centralized (CVCS): CVS, Subversion (SVN)
    - Distributed (DVCS): **Git**, Mercurial
  - Why distributed won 🔴
    - Every clone is a full repository
    - Works offline
    - Fast branching and merging
    - Better for open source
  - Repository (repo)
    - [Local](#) vs [Remote](#)
    - Hosted platforms
      - GitHub
      - GitLab
      - Bitbucket
  - [Git](./Git/README.md) — the de-facto standard 🔴
  - VCS concepts
    - Working directory
    - Staging area (index)
    - Commits and history
    - Branches
    - Tags
    - Merging and rebasing
  - Common workflows 🔴
    - Centralized workflow
    - Feature-branch workflow
    - Gitflow (develop/release/hotfix branches)
    - Trunk-based development
    - Fork & Pull Request (open source)
  - What VCS is NOT
    - Not a backup system (use real backups too)
    - Not for large binaries (use Git LFS or DVC)
